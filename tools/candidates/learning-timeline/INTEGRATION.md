## 作成済みの部品

- runtime-browser.js は12個の実ソースから作成。計測、本人別の再送キュー、履歴読み取り、月別集計を含む。storage.js と calendar-view.js は別に読み込む。
- app.cjs は本体から注入する本人確認とHTTP処理を、計測と月別表示の両方へ接続する候補。同じ本人のセッション更新も別の接続として扱い、前の月別モデルを終了する。25件の隔離検証成功。本体へ読み込む作業・呼出し箇所の接続は未完了。
- client.cjs は本人の切替時に前の計測区間を退避する。退避に失敗したら、新しい本人の計測を始めない。
- month.cjs は history.cjs の全ページ検査が終わってから月別結果を公開。日本時間で月・日を分け、重なる時間を二重に数えない。通信に失敗しても同じ本人の前回結果を残し、本人が変わったら消す。
- calendar-view.js は既存カレンダーの回答記録と別の節に時間を表示。時間を確認できない状態を0分と表示しない。月の切替中も古い月を新しい月と表示しない。

## 検証した範囲

- 月別集計38件：5万区間、ページ境界での重なり、日本時間の月境界、うるう年、通信失敗、別本人、途中の読込みの非公開。
- 既存集計22件、履歴23件（最大500ページ・10万保存チャンク）。
- 実ブラウザ24件：390/1280px、実IndexedDBと既存の計測・本人切替に加えて5万区間の月別集計。
- カレンダー表示26件：390/1280px、更新失敗、月切替の競合、本人終了、誤った0分を出さないこと。
- 最初のブラウザ試行は検証ページにUTF-8指定がなく、日本語の教科照合で失敗。検証ページの文字コードを明示して再実行し、成功。アプリ本体はすでにUTF-8指定がある。
- 保存上限から受取区間の上限は600万。追加のNode検証18件で、600万区間が月外の場合と、600万区間が同一時間帯に重なる場合を各500ページで検査した。同一教科・同一区間は新しい記録だけ保持し、重なる時間は二重に数えない。600万の異なる区間をブラウザへ載せる最大負荷は未検証。実ブラウザで確認済みの5万区間と混同しない。最新ソースから再作成後もブラウザ24件・カレンダー26件は成功。

## 接続する順番

1. 共有本体の全体検証の終了を、既存の同じハンドルで確認する。
2. 新部品を site-assets へ配置し、本人と同意済みのサーバー接続状態から context を作る。認証値を計測DB・ログ・URLへ入れない。
3. 教材台帳と準備済み教科書から正規の活動ID・教科・種類だけを作る。問題の自動開始や実データの採点を行わない。
4. NobiMaterialEntry の活動取得口と既存 NobiTextbook.activity を接続する。問題や教科書を実際に開いていないときは計測しない。
5. 計測用の送信は既存固定経路のPOST、履歴用はGET。共通 request は本文の有無でHTTPメソッドを区別する。どちらも本人の切替前後を検査する。
6. 既存カレンダーの回答履歴を残し、月別モデルと表示部品を追加する。show(host, month, day) へ年月と日付を渡す。カレンダー再描画時に最新のhostを渡す。

8. app.cjs の refresh をログイン・再ログイン・ログアウト時にも呼び、同じ本人の古いセッションを残さない。stop は再実行できるため、保存退避失敗時の再試行へ接続する。
9. 実API＋実画面の隔離検証、月別表示・設定・本人切替を確認してから、共有本体の変更後全体検証を行う。
