# 画面候補の接続条件（未検証）

`view.mjs` と `view.css` は独立候補。本体HTML・既存設定・教材・認証は変更していない。全体検証の既存失敗と確認待ちの間に準備した段階であり、ブラウザ検証成功・機能完成とは扱わない。

`mountCoopView(root, io)` の `io.isCurrent()` はユーザーIDだけでなく、ログイン世代まで固定した既存セッションの判定を渡す。所有者が変われば `destroy()` して問題・入力・表示を消す。表示中の `render()` も同じ判定を通す。

`io.onAction(action, detail)` は既存認証ヘッダーで専用APIへ送り、公開用の集約状態を返す。パスワード・トークン・UIDを画面やURLに追加しない。`create` は信頼できる乱数で部屋IDと招待コードを生成、`join-request` はリクエストID、`purchase` は操作IDを割り当てる。通信結果が不明な場合は同じ操作ID・同じ本文で再試行する。サーバーが決める価格・攻撃力・正誤・クリア・報酬をクライアントから送らない。

`io.renderPrompt(element, question)` は既存の安全な教材描画を接続する。分数を数学・理科とも縦表示し、問題文・数値・図条件を変えず、答えを渡さない。現時点の画面候補は独自の採点や式変換を追加していない。

表示用状態の `state` は戦闘サービスの公開 `state`、`equipment` または `profile` は本人用装備ビュー（コインを含む）。`shop` はサーバーの品目一覧、`story` は物語カタログ、`history` は本人のクリア履歴、`pendingRequests` はホストだけに渡す承認待ち一覧。APIの戻り値をそのまま全面上書きせず、集約アダプターで更新する。

`canHost` はサーバーで本人がホストか確認した結果を接続する必要がある。現行の公開部屋ビューにはこの判定がないため、本体統合時に表示用の真偽値だけ追加すること（UIDや秘密値は出さない）。UIの真偽値だけでサーバーのホスト権限検査を代替しない。

未完了：送信キューと応答喪失時の操作ID保持、サーバー時刻に合わせたカウントダウン、通知・ハートビート・閉じる時の停止と切断、所有者交代時の解除、3クライアントの画面同期、全12章の実表示と通読、画面幅・大きい文字・キーボード・配色・連打時の応答性。特に連打を通信待ちで過度に遅くしない構成は、確定ダメージを偽装しない送信キューと合わせて仕上げる。

2〜3人制限、本人の正解済み問題だけの出題、本人用問題の秘匿、装備価格と攻撃力、同時クリアと同行者履歴はサーバー側が最終判定する。UI候補があることを本体統合・本番反映・実機確認の証拠にしない。
