# のびログ 教科書プロジェクト計画

更新日: 2026-09-27  
状態: 構想・設計段階。教材画面への本番統合や公開はしていない。

## 1. このプロジェクトで作るもの

のびログの「教科書」は、教科書の紙面をそのまま画面に移すだけの機能にしない。中学生が「なぜそうなるのか」を理解し、例を見て、自分で解き、ドリル・ワーク・テストへ自然に進める独自の学習教材を作る。

読んで終わる長い説明ではなく、短い説明のまとまりを連ねる。身近な疑問や場面から始め、図や具体例を使い、解き方を一段ずつ見せ、よくある間違いと確かめ問題を挟む。読みやすく面白くするが、物語や演出が学習内容より目立たないようにする。

## 2. 既に決まっている範囲

- 最初の対象は中学校1〜3年。
- 基本は主要5教科（国語・数学・英語・理科・社会）。
- 保健体育はワーク教材側だけに後から加える構想。ワーク画像を受け取るまでは内容を作ったことにしない。
- ユーザー提供のドリル・ワークを学習の出発点にする。2026-09-27時点で、ドリル4教科222枚（社会なし）、ワークは国語70枚・数学72枚・社会77枚（地理43枚・歴史34枚）。ユーザー指定で全ワークを中1とし、中2・中3のワーク教材は作成しない。追加149枚のページ・単元は照合中。
- 教科書画面はワークモード／ドリルモードとつながるが、本文、例題、問題、正解、出典は別々のデータとして管理する。
- 現在ある数学1年「正負の数」の100問データと、国語ワーク「案内文」の解説原稿は試作資産。全教科の完成を意味しない。
- 既存の成績、答案、学習履歴、本番画面はこのプロジェクトの移行段階で消さない。

## 3. カリキュラムを決める基準

カリキュラムの大枠は、文部科学省の中学校学習指導要領と教科別解説から作る。現行の公式ページには国語・社会・数学・理科・外国語・保健体育など教科ごとの解説が掲載されている。学習指導要領は全国共通の教育課程の基準だが、各学校の単元順や進度そのものではない。そのため、次の二つを分けて記録する。

1. **標準カリキュラム**: 学年、領域、単元、学習目標、前提となる知識。
2. **学校教材の順序**: ユーザーが使うワーク・プリントのページ、問題番号、学校の進度。

単元の目標は、知識・技能、思考・判断・表現、学びに向かう姿勢の観点を意識して作る。教科ごとの「見方・考え方」も単元カードに記録し、単語の暗記だけで終わらせない。

公式資料:

- [文部科学省 中学校学習指導要領解説（平成29年告示・教科別）](https://www.mext.go.jp/a_menu/shotou/new-cs/1387016.htm)
- [文部科学省 中学校学習指導要領（本文）](https://www.mext.go.jp/a_menu/shotou/new-cs/youryou/chu/index.htm)
- [文部科学省「学習指導要領」とは？](https://www.mext.go.jp/a_menu/shotou/new-cs/idea/index.htm)

### カリキュラム表に必要な項目

`教科 → 学年 → 領域 → 単元 → 小単元 → 学習目標 → 前提知識 → 学習順 → 関連問題 → 確認状態`

単元名だけを集めず、「何ができれば学習したと言えるか」「次の何につながるか」まで書く。指導要領にある範囲、学校教材で確認できた範囲、まだ教材がない範囲を区別する。

## 4. 1レッスンの基本形

1. **入口**: 身近な疑問、短い会話、図、予想クイズのどれかで「考える理由」を作る。
2. **今日のゴール**: 学習後にできることを1〜3個、具体的に示す。
3. **前に習ったこと**: 必要な知識だけを短く確認する。
4. **説明**: 1画面1要点を基本に、短文・図・表・式を組み合わせる。
5. **考え方の実演**: 答えだけでなく、どこに注目し、何を根拠に次へ進んだかを順番に示す。
6. **いっしょに解く**: 途中の選択や入力を挟み、すぐに理由つきの反応を返す。
7. **自分で試す**: 2〜5問程度を目安に、基礎から少し難しい問題へ進む。
8. **よくある間違い**: 誤答例、間違える理由、見直し方法をセットで示す。
9. **まとめ**: 今日の要点を短く整理し、重要語・公式・手順を残す。
10. **次へつなぐ**: 対応するドリル、ワーク、テスト、復習へ移動できる。

標準の所要時間は1レッスン5〜10分を仮置きする。実際に使い、長すぎる・短すぎる単元で調整する。

## 5. 教科ごとの作り方

- **国語**: 本文の根拠、段落の関係、語句の働き、表現の効果を順に見る。記述は「何を書けば条件を満たすか」を説明し、模範解答の丸暗記にしない。
- **数学**: 図や具体数で意味をつかみ、式の各変形に理由を付ける。途中式、単位、検算、別解を扱う。数値の正誤は決定的に検証する。
- **英語**: 音・意味・語順をつなぎ、短い例文から文法を組み立てる。読み上げは端末標準の音声を使う。音源のないリスニング問題は推測で補わない。
- **理科**: 現象の予想、観察・実験、結果、説明の順にする。図のラベルや条件を元画像と照らす。単位、数値、因果関係を別々に確かめる。
- **社会**: 地図・年表・資料・統計を読む手順を教え、出来事を原因・変化・結果でつなぐ。統計や制度など変わる情報は出典と確認日を持たせる。
- **保健体育**: ワーク教材が届いた段階で対象範囲を決める。体の安全や健康に関わる説明は公式情報を使い、一般化しすぎない。

## 6. データの分け方

本文と問題を一つの大きな文章へ埋め込まない。教材の修正や差し替えがしやすいよう、次の単位で管理する。

- `curriculum`: 教科・学年・領域・単元の地図
- `lesson`: 目標、前提、説明ブロック、例、図、まとめ、次の学習先
- `question`: 問題文、解答、採点法、難易度、出典、原題／類題の区分
- `source`: ファイル名、ページ、大問、小問、画像内の位置、確認者、確認日
- `review`: 教科内容、解答、文章、表示、アクセシビリティの確認状態
- `progress`: 安定したlesson/question IDを使った学習記録。表示文の変更で回答履歴を切らさない。

各レッスンは `draft → source_checked → answer_checked → reviewed → ready` の状態を通す。状態を飛ばして公開しない。OCR結果だけでは `source_checked` にできない。`ready` は、確認者が `verified:true` にした出典台帳レコードのID・SHA-256・モード・教科・学年・ページと、問題・説明の参照が一致した場合だけ許可する。ワーク差し替えでハッシュが変わったら再確認する。

`ready` の教材データには、目標・要約・出典つきで人が確認した説明節、ちょうど100問の入力式練習問題、少なくとも1問の別問題テストが必要。テスト問題は練習問題と同じ文面を使わず、類題として区別する。教科書・練習問題・テストの各出典に、台帳の `source ID + SHA-256 + mode + subject + grade + file + page + number` を付ける。アプリへ教材を渡す画面は同じ出典台帳を検証器へ渡し、台帳と結び付かない単元を一覧・出題対象へ出さない。

## 7. 採点と問題作成のルール

- 問題には教科・学年・単元・出典住所・原題または類題・難易度・解答・解説を付ける。
- 原題の解答は自力で解き、独立した計算または本文根拠で再確認する。
- 類題は数字や条件を変えるだけでなく、同じ学習目標を測るか確認する。
- 正解を作れない問題、見えない図、欠けた選択肢、音源待ちは下書きに残し、出題しない。
- 数値・分数・単位は意味が同じ入力だけ許容する。国語記述は問題ごとに必要要素を定義する。
- 70%採点は共通の文字類似度で決めない。問題の要点、必須語、矛盾・否定条件を項目ごとに採点し、基準を問題データと検証へ残す。
- 「惜しい」半点は、何を満たしたら半点か先に定義できる問題だけに付ける。
- 1単元100問は目標であり、根拠のない繰り返しや言い換えで数を水増ししない。

## 8. 画面の構想

教科書タブは、教科・学年・単元・レッスンの順で選ぶ。レッスン画面には「読む」「例を見る」「自分で試す」「ドリルへ」「ワークへ」「テストへ」を置く。学習途中でモードを行き来しても、どこまで進んだかが分かるようにする。

ユーザー指定により、教材画面の最上部に教科書タブを置く。ワーク原本が未提供・未照合の単元は本文を作らず空欄で保持し、教科書タブだけを灰色の「準備中」状態にする。原本を照合して単元を作り始めるまでは押せない表示とする。既存のドリル・検定など他の入口の状態は変えない。

- 既存アプリの丸みのある見た目を引き継ぐ。
- スマホは1列で読みやすく、操作対象を大きくする。PCは余白と図表を生かす。
- 読み上げ、文字サイズ、ふりがな表示は必要性を確認し、設定に合わせて使えるようにする。
- 動きは理解を助ける場面だけにし、動きを減らすOS設定に従う。
- 白黒印刷でも図、番号、正誤が分かるよう色以外の手掛かりを付ける。

## 9. 使用するソフトと役割

- **OpenCode + GPT-oss:20B**: 実装の補助、原稿の初稿、形式チェック。出力をそのまま正答・事実として採用しない。必ず原資料と検証で確認する。GPT-ossは開発時のAIであり、アプリの回答採点に自動接続されているわけではない。
- **Apple Vision**: Mac上の教材画像OCR。検索・索引づくり用で、誤認があるので人が画像を確認する。
- **`sips`**: HEIC教材を確認しやすい画像形式へ変換する。
- **Node.jsの隔離ハーネス**: 採点、保存、同期、問題数、権限、重複、出典の検証。利用者の実データを使わない。
- **Cloudflare Workers**: 認証済み保存・同期API。変更時は `SECURITY.md` を先に読み、認証情報を表示しない。
- **Cloudflare Pages**: 公開画面。ユーザーが公開を明示したときだけデプロイする。
- **ブラウザ `speechSynthesis`**: 無料の端末標準読み上げ。英語 `en-US`、日本語 `ja-JP`。採点根拠には使わない。
- **Microsoft Edge「音声で読み上げる」**: 原稿や発音の手動確認用。
- **Mac `say`**: 固定音声ファイルが必要になった場合の教材制作候補。現時点で一括音声生成はしない。
- **PDFプレビュー／印刷**: ワーク原典の目視、完成原稿の白黒印刷確認。文字化け、図の欠落、ページ切れを確かめる。

## 10. 品質ゲート

レッスンを `ready` にする前に、次を全部確かめる。

1. 学習目標が指導要領の範囲と一致し、学年が正しい。
2. 教材由来の説明・問題には出典ID・原本ハッシュ・モード・教科・学年・ページ・問題番号を記録し、原典を目視した。台帳の同じモード・教科・学年・ページで確認済みになっている。
3. 正答は自分で解き、別の方法でも確認できる箇所は二重確認した。
4. 問題、解答、解説、図が同じ問いを指している。
5. 類題は重複せず、同じ目標を測り、難度も段階的である。
6. 日本語が自然で、中学生が一度読んで意味を取れる。
7. PC・スマホで読めて、白黒印刷、読み上げ、文字拡大でも内容が失われない。
8. 誤答・空欄・表記ゆれ・単位・分数・矛盾回答の採点を隔離データで確認した。
9. `ready` の本文、100問、類題テストがすべて照合済み出典へ結び付いている。
10. 既存の成績、答案、ログイン、同期、通知へ副作用がない。
11. 進捗ファイルへ確認者、日付、検証結果、未解決事項を記録した。

## 11. 段階計画

| 段階 | 作業 | 完了の目安 |
|---|---|---|
| 0. 範囲設計 | 指導要領と教材を単元地図へ整理。学年・教科・出典・未提供範囲を分ける | 主要5教科×3学年の15区分カリキュラム表と未確認一覧ができる |
| 1. 形式設計 | lesson/question/source/reviewのデータ形式と確認状態を定義 | 既存教材1つを新形式へ変換し、旧データを壊さず読み込める |
| 2. 試作 | 数学「正負の数」と国語「案内文」など、性質の違う2単元を試作 | 解説、例、確認問題、出典、採点、スマホ表示を通して評価できる |
| 3. 教科別制作 | 5教科を単元単位で制作。教材が届いた範囲からワークモードも作る | 品質ゲートを通過した単元だけをreadyにする |
| 4. アプリ接続 | 教科書タブからドリル・ワーク・テストへ連携し、進捗をサーバー保存 | 2アカウント分離、保存失敗、再ログイン、端末間同期を隔離検証する |
| 5. 小規模公開 | ユーザーの明示指示後、完成した単元だけを公開 | 配信ファイル・認証・端末幅・印刷・通知を配信後に確認する |
| 6. 継続改善 | 誤り報告、教材追加、学習記録に基づいて改訂 | 変更履歴と旧回答への影響を記録し、古いデータを壊さない |

全学年・全単元の完成には相当量の原典確認と制作が必要。最初から公開範囲を大きく見せず、完成単元と準備中単元を明確に分ける。

## 12. 今の資産と最初の着手点

- 画像441枚の一覧・出典台帳がある。既存292枚はOCR台帳と照合済み。追加の数学72枚・地理43枚・歴史34枚は出典・ハッシュを登録済み、学年はユーザー指定で中1、ページ・単元は未確認。
- 数学1年「正負の数」は教材整理内に100問とテスト15問がある。試作教材の形式を考える材料にできる。
- 理科「光の性質とレンズ」は9問のdraft。正答と全体単元を確定するまでは出題対象にしない。
- 国語ワーク「材料を整理して案内文を書く」の教科書原稿は初稿。ページと学年は未確認。
- 英語「現在進行形」はp46〜47を確認した。音声が欠ける設問があり、その問題を推測で補わない。

2026年9月27日に初版の「中学校5教科×3学年カリキュラム地図」を作成した。文部科学省の基準範囲とユーザー提供教材の照合状況を分け、全15区分の本文は空欄・準備中にした。学校ごとの配当が一律でない英語の文法順などは決めつけず、社会は第1・2学年に地理・歴史、第3学年に歴史・公民を並行・継続する標準を反映した。タブの準備中表示はアプリに追加したが、本番公開はしていない。

次の作業は、全ページを一度に原稿化することではない。まず「標準カリキュラム表」の最小版を作り、441枚の教材のうち未照合分を単元・学年・ページごとに確認する。その後、数学と国語の試作を同じレッスン設計に当てはめ、読みやすさと学習効果を比べる。

## 13. 今後ユーザーと決めること

以下は仮置きであり、ユーザーの希望を聞いて更新する。

- 最初の試作単元を数学「正負の数」と国語「案内文」の2つで進めるか。
- 1回に読む量を5〜10分程度にするか。
- ふりがなを常時表示にするか、設定で切り替えるか。
- 登場人物やストーリーを薄く使うか、身近な実例を中心にするか。
- 一般公開する説明と、本人のワーク・ドリルを使う限定教材をどう分けるか。

ユーザーから決まった回答が届く前も、リスクのないカリキュラム整理や原稿の棚卸しは進められる。決定によって教材の方向が大きく変わる制作へ入るときは、既に明示された希望を優先する。
