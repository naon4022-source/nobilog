# 採点機能の実装依頼（Claude → Codex・2026-10-14）

教材の原稿（特訓・検定）を作る中で、今の採点エンジン（`教材整理/実装/material-engine.js`）では正しく採点できない答え方が見つかった。
Claude はエンジンを変更していない。原稿側で回避できるものは回避し、回避できないものをここにまとめる。
再現例は `教材整理/特訓下書き/probes/` の JSON（入力と期待する判定）と、下の表にある。

## A. いまの原稿では「扱わない」ようにしているもの（扱えると偽っていない）

| 種類 | 必要な機能 | いまの原稿の扱い |
|---|---|---|
| 平方根をふくむ答え（例：2√3、3√2/2） | √の式として、係数・中の数を簡単にした形どうしで比べる（√12 と 2√3 を同じとみなすか、簡単にした形だけ正解にするかを選べる） | 数検3級で、答えが整数や分数になる問題だけにした |
| π をふくむ答え（例：4π、12πcm²） | いまは exact の文字列一致。「4π」「4 π」「4×π」を登録して対応。π を記号として扱う式の比較があると安全 | 数検5級のおうぎ形3問は exact で表記ゆれを登録 |
| 証明（三角形の合同など） | 仮定・結論・合同条件・根拠の順序を見る記述採点、または段階ごとの穴うめ形式 | 合同条件を「選ぶ」問題だけにした |
| 作図 | 図の上の操作（コンパス・定規）の記録と判定 | 入れていない |
| 図を見て答える問題 | 図の配置（README の配置ID表）を教材に入れる仕組み | 図がなくても解けるよう、条件を文章で書いた |

## B. 原稿側では直しきれない採点の問題（エンジン側の対応が必要）

| # | 内容 | 再現例 | 期待する判定 |
|---|---|---|---|
| 1 | 記述の字数制限を数えない | tokkun-japanese-1-kaku「駅前の花だん」（四十字以内）に63字の答え → 正解になる | 字数をこえたら「字数をこえています」と不正解（または減点） |
| 2 | キーワードを並べただけの答えも正解になる | 同じ問題に「お年寄り　水　から」→ 正解になる | 文として成り立たない答えは不正解（最低字数や、助詞・述語の有無の確認など） |
| 3 | 否定の判定が「ない／なく」の文字列だけで行われる | 「つないで」「少ない」「間もなく」「だけでなく」をふくむ正しい答えが不正解になる（例：国語「連歌」の説明、社会・理科の記述多数） | 否定の語として使われている場合だけを否定とみなす。特訓の下書きでは `allowNegation` と `reject`（逆の意味の書き方）を組にして回避している |
| 4 | 確認済みの理科 ready 単元の記述 | Codex が5問（hansha69・kitai24・kubetsu22・youkaido19/66）を修正済み。ほかの確認済み単元にも、模範解答に「ない」が入る記述が残っていないかの一括点検が必要 | 上の3と同じ |

## C. 原稿側で回避した方法（Codex が統合するときに知っておくこと）

- 特訓下書きの記述問題で、自然な答えに「ない／なく」が入るものは `allowNegation: true` と `reject`（逆の意味になる書き方の語）を必ず組にした（`tokkun_textbook.py` の `RN`）。
- 「すべて答える（set）」で記号だけの組は `letters: true`、語句の組は `plain: true` と、問題文に「（「、」で区切って書こう）」を入れた。
- 数の答えに「何％」「何ポイント」「何万人」「いくつ」などの単位を補った。
- 並べかえ問題は、与えた語を短縮形から戻した答え（I'm→I am など）を正解にしない。
