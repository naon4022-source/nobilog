# 検証方法（Claude 2026-10-27）

すべて作業フォルダの中だけで実行した。実ユーザーの記録・ブラウザ・全体検証（run.sh）は使っていない（全体検証は Codex が実行中のため重複起動しない）。

## 手順（1単元ごと）
1. `python3 build/build_tokkun_social_<名前>.py` … 問題を組み立てて `原稿/` に書く。
   - 組み立ての中で、ワーク・ドリル（確認済みの同じ範囲）との似ている度と、特訓どうしの似ている度を測る。0.9以上は止まる。0.6以上は一覧に出し、目で確かめた。そっくりな問題は差しかえた（例：ガンジス川・メッカ・アラビア語・奴隷の問題）。
   - 教科書ページを出典にする問題は、台帳登録案の checkLevel が「本文」でないと止まる。
   - 出典が正式台帳の verified の行に結び付かない問題が1つでもあると ready にしない。
2. 選択肢の直しを `選択肢修正/<単元ID>.json` に書く（`build/mkfix.py`）。正答の言いかえは意味を変えない範囲だけ。
3. `python3 build/finalize.py <単元ID>` … 直しを当て、答えの位置を問題IDから決まる順でならべかえる。解説・答えの記号も一緒に付けかえる。結果は `候補/`。
4. `node build/check_tokkun_draft.cjs 候補/<単元ID>.json` … 本物の採点エンジン（material-engine）で次を確かめる。
   - 形式の検査（validateUnit）
   - 全問で、登録した正答が「正解」になる
   - 答えをくずした入力が「不正解」になる
   - 出典の SHA-256・verified・ページ
   - 問題文の重なりがない
   - 70問
5. `python3 build/audit_choices.py 候補/<単元ID>.json` … 1つ選ぶ問題で、答えの位置がかたよっていないか、正答の選択肢だけが目立って長くないか（2番目に長いものの1.25倍をこえる）を数える。24単元とも 0 にした。

## 計算と事実の確かめ方
- 数の答えは build の中で分数（Fraction）で計算した。時差は datetime で計算し、さらに手で全部たしかめた。
- 事実は、その場で地理教科書の写真（台帳の画像）を開いて読んだものだけを使った。今回読んだページ：p10〜15・20、p36〜53、p74〜79・84・88〜95・98〜101、p104〜107・112〜115。
- 1つ選ぶ問題は、まちがいの選択肢が教科書の内容とはっきり食いちがうことを確かめた。グラフの国を選ぶ問題は、グラフにある国だけを選択肢にした（ヨーロッパ29：デンマーク・ドイツ・スペイン・日本）。
