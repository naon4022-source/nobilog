# R2 への毎日の暗号化バックアップ（候補・未反映）

- 決まっていること：保存先は R2（ユーザー回答「R2でいいんじゃないかな」）。毎日・暗号化。
- `backup-r2.mjs`：
  - その日（日本時間）の分を `backups/YYYY-MM-DD.enc` に1つ置く。同じ日は作り直さない。
  - AES-256-GCM で暗号化。名前も一緒に確かめるので、別の日の名前へ移したものは復元できない。中身の SHA-256 で照合する。
  - 鍵は `BACKUP_KEY`（32バイト・base64）。鍵がなければ何もしない。鍵・行の中身はオブジェクトの情報に入れず、件数だけ入れる。
  - 古い世代を外すのは、`keepDays` を明示したとき（7日以上）だけ。初期は消さない。
  - 復元は `restorePlan` で「下書き」まで。復号・照合して行を返すだけで、本物のデータへは書き戻さない（人が確かめてから）。
- 確認：`node verify-backup-r2.mjs`（合成の行・メモリのにせ R2・14件）。本物のデータ・バケット・鍵は使っていない。

## 費用のめやす（無料枠の保証はしない）
- R2 の無料枠（私が知っている範囲の数字。今日は公式ページで確かめていない）：保存10GB/月、書き込み（Class A）100万回/月、読み出し（Class B）1,000万回/月。外へ出す通信は無料。
- 1日1回の put＋head＋list で、月に約90回。保存量は「家族の記録の合計 × 保持する日数」。家族の記録が数MBなら、30日保持でも数百MB程度の見込み（実際の大きさは測っていない）。
- 料金・無料枠は変わることがあるので、有効にする前に Cloudflare の最新の料金ページで確認する。

## 決めたこと（2026-10-22 ユーザー「適当に決めておいて」）
1. 残す期間：毎日の分は30日、各月1日の分は12か月（`POLICY`。最大で約42個）。
2. 鍵：Worker Secrets の `BACKUP_KEY`（32バイト）。登録はなお本人が行い、同じ値をパスワード管理アプリにも控える（なくすと復元できない）。鍵を変えるときは、古い鍵も1年は控えておく。
3. 中身：学習の記録だけ（KV BOARD・D1 の学習テーブル）。認証ストア・セッション・秘密値は入れない。
4. 復元：なお（u1）だけ。下書きで中身を確かめてから書き戻す。
5. 実行：毎日 日本時間 午前3時（cron `0 18 * * *`）。登録は公開のときにまとめて行う（いまは登録していない）。
6. なおの Mac への控え：あとで手順を作る。
確認：`node verify-backup-r2.mjs` 16件（30日＋月1回12か月の残し方を含む）。

## 取り込み（Codex）
- wrangler.toml に R2 バインディング（例：`BACKUP`）を足し、`scheduled()` から `runBackup(env, env.BACKUP, exporters)` を呼ぶ。exporters は KV/D1 を1件ずつ読む形で渡す。バケット作成・Secrets 登録・cron 登録はユーザーの確認後。
