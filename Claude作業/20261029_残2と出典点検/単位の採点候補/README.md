# 単位つきの入力が×になる件の独立候補（2026-10-29 Claude）

**候補だけ。どの原稿も、共通の採点エンジンも変更していない。** 採点は `教材整理/実装/material-engine.js` を読むだけで使った。

## 再現
- 「π を使って答えよう（cm³）」のように答えの単位を指定した問題で、答え（answer）に `units` が登録されていないと、「32π cm³」のように**数学的に正しい単位つきの入力が×**になる（「32π」だけなら○）。
- `scan_units.cjs` で、完成候補の全単元（`../../20261029_立体残7/原稿` と `../原稿`）をさがした。**106問**（georeview 44・circlecalc 39・volume 16・solid2 3・solidmake 2・solidreview 1・surface1 1）。どれも、元のデータで「答え＋単位」が×になることを確かめた（再現 106/106）。
- 1回目のさがし方は、表の見出しの「（kg）」なども拾って広すぎた（176問、`scan_units_1回目_広すぎ.cjs`・`scan-result_1回目_広すぎ.json`。人数を答える問題に kg をつけるなど、まちがった候補が入っていた）。「〜答えよう（cm²）」「〜求めよう（cm）」の形で答えの単位を指定している問題だけにしぼって作りなおした。

## 修正案（`修正案_units.json`）
- 106問の `answer` に `units` を足すだけ（cm² は ['cm²','cm2']、cm³ は ['cm³','cm3']、m² は ['m²','m2']、cm・m はそのまま）。問題文・答えの値・解説・出典は変えない。
- `solidreview-1` は、最新の候補 `../原稿/tokkun-math-1-solidreview.json` でも同じ問題（元の3問は変えていない）。足すときは最新の候補のファイルに入れる。

## 副作用の検査
- `test_patch.cjs`：修正後のメモリ上の写しで、1問あたり7通りを本物のエンジンで採点。**742件・期待とちがう0**（`test_patch.log`）。
  - 単位なしの答え ○ のまま／正しい単位（全角・cm2 などの書き方）○／**ちがう単位（cm と cm² の取りちがえなど）×**／値をこわした答え（(答え)+1）×／π をつけ忘れた答え ×。
  - 1回目は「1」を前につけた答えを誤答にしたが、π/10 と 1π/10 は同じ値で、**検査側の誤り**だった（`test_patch_1回目.log`、期待とちがう1件）。誤答の作り方を直して再実行した。
- `validate_patch.cjs`：修正を入れた7単元を `validateUnit` で調べ、ふえたエラー0（`validate_patch.log`）。

- エンジン側で「問題文の（cm²）を見て単位を受けつける」ように直す方法もあるが、共通エンジンなので今回は作っていない。
