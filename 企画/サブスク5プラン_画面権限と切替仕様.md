- **確認版のログインは、今はアカウントが1つだけ**（`preview/src/index.mjs`）。

## 2. 大型アップデート後の初回起動と、なおのUNLIMIT開始

### 2-1. 決まり【決定】
- 原則、全員 **Free** で始まる。例外は **なお本人の既存アカウントだけ**で、最初から **UNLIMIT**。
- なおの判定は名前ではなく、**正確な既存ID**で行う。
- 運営者用のUNLIMITは、**支払い確認の記録と区別する**。
- 保存ずみの学習記録は引き継ぐ。初回設定は**1回だけ**。2回目以降の起動でFreeに戻したり、買ったプランを上書きしたりしない。

### 2-2. しくみ【提案】
- サーバー（本編の認証D1）にアカウントごとの「契約」を1行持つ。項目の例：プラン、状態（有効／解約中）、開始日、終了日、**版番号**（変更のたびに1増える）、**理由の種類**（初回設定／運営者／支払い確認）、初回設定ずみの印。
- 初回設定は**サーバーで1回だけ**行う。「契約の行がまだ無いときだけ作る」形にして、すでに行があれば何もしない（同時に2台で起動しても1回だけになる）。
- なおの判定：**本編の認証D1にある、なおの正確な既存ID**と一致したときだけUNLIMIT、理由は「運営者」。それ以外は全員Free、理由は「初回設定」。
  - 確認版は別のD1で、uidが本編と同じ `u1` のため、**確認版ではこの例外を使わない**（0章）。
  - 名前・表示名・メールでは判定しない。
- 運営者のUNLIMITは**終了日なし**か、【未確定】。支払い確認の記録（5章）には入れない。

### 2-3. 画面と順番
1. ログインを確かめる。
2. 「**のびログを準備しています**」を出す。
3. サーバーに初回設定を頼む（すでに設定ずみなら、今の契約を返すだけ）。
4. 結果によって表示する。
   - Free：「**大型アップデート後は、Freeプランからスタートします。**」
   - なお：「**なおのアカウントは、UNLIMITプランでスタートします。**」
5. 学習記録はそのまま。契約に合わせて画面を用意してから、ホームを開く。
- 初回設定の通信に失敗したら、**Freeと決めつけない**。4章の「確認できませんでした」と再試行を出す。
- 2回目以降の起動ではこの画面を出さない。今の契約を読むだけにする。

## 3. プランを変えたときのロード画面と処理の順番

### 3-1. 文言【決定】
- 変更中：「**プランを変更しています**」「**StandardからProへ切り替えています。**」「**学習記録を引き継ぎ、使える機能を準備しています。**」
- 完了：「**Proプランへの変更が完了しました**」「**AIチャットとノート分析が使えるようになりました。**」
- 完了の文には、**実際に増えた機能**を短く書く。架空の進み具合（％）や、時間がたつだけで完了する演出はしない。

### 3-2. 変更に気づく方法【決定＋提案】
- アプリを開いたまま変更されても、**次の通信**か**画面に戻ったとき**に気づく【決定】。
- 方法【提案】：サーバーの返事に、いつも契約の**版番号**を入れる。アプリは覚えている版番号と比べて、違えば変更の処理を始める。画面に戻ったとき（`visibilitychange`）にも、版番号だけを聞く。

### 3-3. 処理の順番【提案。「契約確認→設定更新→画面準備が終わってから新機能」は決定】
1. 版番号の変化に気づく。
2. **書いている途中のノート・回答を先にサーバーへ保存する**【決定】。保存できたことを確認する。
3. 有料機能の操作を止める（古いプランの機能もここで止める）。ロード画面を出す。
4. **契約の確認**：サーバーから新しい契約（プラン・期限・残り回数・使える機能の一覧・版番号）を受け取る。
5. **設定の更新**：アプリの中の契約の情報を、受け取ったものに入れ替える。
6. **画面の準備**：入口ボタン・マイページ上部・各画面の表示を作り直す。
7. 完了の文を出す（増えた機能／使えなくなった機能）。
8. 完了してから、新しい機能を使えるようにする。

- 3〜7の間は、**古いプランと新しいプランの画面を混ぜない**【決定】。
- 「増えた機能」は、変更前と変更後の「使える機能の一覧」の差から作る【提案】。例：Standard→Pro なら、AIチャット、教科書への書き込み、まとめノート、ノート・苦手分析、復習問題、AI回数 月150→300回、活動履歴 3週間→1か月。
- 下のプランにした場合の文言は、指示に無いので【未確定】。案：「Miniプランへの変更が完了しました」「AIチャットは使えなくなりました。書いたノートと記録は残っています。」
- サーバー側は、変更が保存された**その時点から**新しい権限で判断する。アプリの切り替えが遅れても、上のプランの機能をサーバーが許すことはない【提案】。

## 4. 変更の失敗・再試行・別の端末・編集中の扱い

### 4-1. 失敗したとき【決定】
- 通信に失敗しても **Freeに戻さない**。
- 失敗したら「**変更を確認できませんでした**」と、**再試行ボタン**を出す。
- **一定時間でタイムアウト**して、状況と再試行のしかたを案内する。タイムアウトの秒数は【未確定】（案：20秒）。
- 確認できない間は、**有料機能の新しい操作だけを止める**。無料の学習機能はそのまま使える【提案】。

### 4-2. 再試行・別の端末【決定】
- 再試行しても、別の端末で起動しても、**AIの回数や契約期間をリセットしない**。
- 途中で閉じても、次の起動で**安全に続きから確認**する。
- しくみ【提案】：
  - 回数と期間は**サーバーだけが持つ**。アプリは表示するだけ。
  - 回数は「アカウント＋期間の開始日」ごとに数える。同じ送信IDの再送は1回だけ数える（前回文書9章）。
  - アプリは「最後に確認した版番号」だけを覚え、起動のたびにサーバーと比べ直す。途中で閉じても、次の起動で4章の手順をやり直すだけで、何も二重には起きない。
  - 2台で開いている場合、どちらの端末も同じ版番号を見て、それぞれ切り替える。

### 4-3. 編集中のもの【決定＋提案】
- **権限を切り替える前に保存する**【決定】。
- 保存に失敗したら【提案】：切り替えを始めず、書いたものを端末に残したまま「保存できませんでした」と再試行を出す。書いたものを捨てて切り替えることはしない。
- 下のプランに変わって編集ができなくなっても、**書いたノート・答案は消さない**【決定】。

## 5. なおによる支払い確認と、契約変更の手順

### 5-1. 決まり【決定】
- 利用者は**なおに相談**し、なおが**直接お金を受け取る**。カードの自動課金は作らない。
- 利用者の「払った」という申請だけでは切り替えない。**なおの受け取り確認が必要**。
- 変更は、**なおの明示の指示**にもとづいて、Claude・ChatGPT・admin のどれかから行う。

### 5-2. 手順
1. 利用者がなおに相談する（希望のプラン・期間）。
2. なおがお金を受け取る。
3. なおが、Claude・ChatGPT・admin のどれかに**はっきり指示する**（だれの・どのプランに・いつからいつまで）。
4. 指示を受けた側が、変更の内容（対象・旧→新・開始日・終了日）を**なおに見せて確認をとる**【提案】。
5. サーバーの契約を変え、**同時に記録を1件書く**（下の8項目）。
6. 利用者のアプリは、次の通信か画面復帰で気づき、3章の手順で切り替わる。

### 5-3. 記録する項目【決定】
| 項目 | 内容 |
|---|---|
| 変更した人 | Claude／ChatGPT／admin（＋操作した人） |
| 対象アカウント | 正確なID |
| 旧プラン | 変更前 |
| 新プラン | 変更後 |
| 開始日 | 新しい契約の開始 |
| 終了日 | 新しい契約の終了 |
| 変更日時 | サーバーの時刻 |
| 理由 | 例：「支払い確認（なお）」「運営者」「初回設定」 |

- 記録は**あとから書き換えない・消さない**形にする【提案】。まちがえたときは、正しい内容の記録を新しく足す。
- 金額や受け取りの方法を記録に入れるかは【未確定】。入れる場合も、口座番号などの支払いの情報は書かない。

### 5-4. 注意点【提案】
- 変更の入口（admin）は、なお本人か、なおが許した運営者しか使えないようにする。**利用者のアプリからは変更できない**。
- Claude・ChatGPTが変更するときも、**チャットに「払った」と書かれていただけでは変えない**。なお本人の指示であることを確かめる。
- Claude・ChatGPTはお金を扱わない。プランの変更（サーバーの操作）だけを行う。
- 期間が終わったときの扱い（自動でFreeに戻すか、なおに知らせるか、猶予を置くか）は【未確定】。自動課金が無いので、**終了日の前に本人となおへ知らせる**案。

## 6. 4つの確認アカウントの設計

### 6-1. 決まり【決定】
- Mini・Standard・Pro・UNLIMIT の確認版を、**別々のパスコード**で入れるようにする。
- 会話・ノート・履歴・AIの回数は、アカウントごとに**分ける**。
- パスコードは**非表示の登録画面で本人が設定**し、チャット・コード・ログへ書かない。
- 画面・上限・変更のロード・初回のロード・解約と再契約を試せるようにする。
- **実際の課金・実際のAI接続と、模擬の動きを混同しない**。

### 6-2. 今の確認版との差（0章より）
| 今 | 4アカウントに必要なこと【提案】 |
|---|---|
| uidは `u1` に固定 | アカウントごとに別のuid（例：`p_mini` `p_standard` `p_pro` `p_unlimit`）。本編のID（`u1` `u2` `x_...`）とは重ならない名前にする |
| 利用権のキーは `active-session:u1` 1つ | アカウントごとに別のキー。1つにログインしても、ほかのアカウントの端末を追い出さない |
| パスコードの検証値は secret 1つ | アカウントごとに別の検証値 |
| 失敗の回数はIPごと・全体 | 今の上限（IPごとに15分5回、全体20回）は残し、アカウントごとの上限も足す |

### 6-3. パスコードの登録【提案】
- 登録画面は、ふだんの画面からリンクしない（非表示）。
- **なお本人が自分で入力**する。Claude・Codexは値を聞かない・見ない・書かない。
- サーバーは検証値（今と同じく pepper を使ったHMAC）だけを保存する。**元のパスコードは保存しない。検証値から元に戻せるとも説明しない**。
- 登録画面は、だれでも使えないように守る。案：まだ登録されていないアカウントだけ登録できる。登録しなおすときは、今のパスコードか運営者の確認が必要。
- 登録・失敗のログに、入力した値を残さない。
- Cloudflare Secretの値は読み戻さない。名前だけを確かめる（`SECURITY.md`）。

### 6-4. 試せるようにすること【決定＋提案】
| 試すこと | 方法【提案】 |
|---|---|
| 画面 | 各アカウントでプランどおりの入口が出る／出ない |

### 7-2. 検証項目（実装のあと、隔離ハーネスで確かめること）
- **権限**
  - 5プランそれぞれで、有料APIを直接呼んで、下のプランなら拒否されること。
  - ブラウザから送ったプラン名・残り回数が無視されること。
  - 画面に入口が出る／出ないが、1-3の表どおりであること。
- **初回起動**
  - なおの正確なIDだけがUNLIMIT、ほかは全員Freeになること。
  - 名前が「なお」の別アカウントはFreeになること。
  - **確認版の `u1` はUNLIMITにならないこと**。
  - 2回目以降の起動で変わらないこと。2台が同時に起動しても1回だけ設定されること。
  - すでに買ったプランを上書きしないこと。
  - 学習記録が残ること。
- **変更**
  - 版番号の変化を、次の通信と画面復帰で検知すること。
  - 編集中の内容が、切り替えの前に保存されること。保存に失敗したら切り替えないこと。
  - 古いプランと新しいプランの画面が混ざらないこと。
  - 完了の文の「増えた機能」が、実際の差と一致すること。
- **失敗**
  - 通信に失敗してもFreeに戻らないこと。「変更を確認できませんでした」と再試行が出ること。
  - タイムアウトすること。
  - 再試行・別の端末・途中で閉じたあとでも、回数と期間がリセットされないこと。
  - 同じ送信IDの再送が1回だけ数えられること。
- **下げる・再契約**
  - 答案・成績・自分のノートが消えないこと。
  - UNLIMIT専用のものが非表示になり、再契約で再表示されること。
  - 保管期限が未確定の間は、何も削除されないこと。
- **記録**
  - 変更のたびに8項目が1件書かれること。あとから書き換えられないこと。
  - 利用者の「払った」申請だけでは変わらないこと。利用者のアプリから変更できないこと。
- **確認アカウント**
  - 4つが別々のパスコードで入れること。
  - 会話・ノート・履歴・回数が混ざらないこと。
  - 1つにログインしても、ほかの端末を追い出さないこと。
  - パスコードがコード・ログ・応答に出ないこと。
  - 本編へ記録が移らないこと。
  - 模擬と本物が画面で区別できること。
- **実機（未確認のまま残るもの）**
  - iPhone・Macで、画面に戻ったときの検知とロード画面の表示。
