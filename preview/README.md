# のびログ専用アカウントの確認版

### OpenAIキーの登録準備（2026-10-13）
`register-openai-local.py` は、このMacの127.0.0.1だけでキー入力画面を開く。確認版構成とAI停止設定を検査し、Wranglerで秘密名だけ確認してから入力を受け付ける。OpenAIキーはstdinでnobilog-previewのOPENAI_API_KEYに登録し、コード・ファイル・ログへ保存せず、既存のキーは上書きしない。外部Origin・偽Host・CSRF不一致を拒否する。入力は人が行い、エージェントはキー欄・クリップボード・作成後のAPIキー画面を読み取らない。
登録は有料APIの有効化ではない。支払いと本人の確認後、別途接続検査を行う。実AI試験は全利用者共通で1日10回まで、追加はユーザー許可待ち。登録画面が閉じた場合はキーをチャットへ送らず、もう一度画面を開いて再開する。登録結果が不明なら自動再送せず、秘密名の有無だけで確認する。

この環境は作業中の機能を確認するためのもの。本番の記録・認証・保存先には接続しない。アカウント名は「確認版」。パスワードはユーザー指定の値を `set-password.py` の非表示入力で設定し、原文をファイルへ保存しない。

## 接続準備

1. Cloudflareの公式ログインを完了する。
2. `nobilog-preview-store` のD1と、`nobilog-preview-board` のKVを新規作成し、返されたIDだけを `wrangler.jsonc` に設定する。本番のIDを転用しない。
3. 専用D1へ `../cf-worker/migrations/0001_auth_store.sql` の空のスキーマを適用する。本番からデータをコピーしない。
4. `python3 preview/set-password.py` でパスワードを設定する。既存秘密値を読み戻さない。
5. `bash preview/deploy.sh` で専用確認版を配信し、未認証時の拒否とログイン画面を確認する。
   端末通知の署名設定は `node preview/set-notification-key.mjs` で新規作成する。既存の署名鍵は読み戻さず、存在する場合は変更しない。

## 保存と公開

- 確認版のCookieはHttpOnly/Secureで、APIの入力からユーザーIDを指定してログインすることはできない。ログイン回数と同時使用をサーバーで制限する。
- 確認版の学習・設定・ゲーム記録は専用D1/KVへ保存する。ブラウザを閉じて再ログインしても専用サーバーから再開する。
- 確認版のService Workerは通知専用で、画面・記録を端末へキャッシュしない。通知許可は設定ボタンを押した時だけ要求する。更新と学校行事は毎時の定期処理で送信し、実績は申請/確認時に送信する。種類ごとの停止、重複防止、本人端末だけの送信を使う。Chrome/Mac/Androidは通知許可、iPhoneはホーム画面追加と通知許可が必要。
- 本人が発行した「問題だけのPDF共有リンク」は例外として、リンクを知っている相手がログインなしで7日間開ける。作成・一覧・停止は本人認証が必要。PDFは確認版専用KV、期限と所有者は専用D1へ保存し、本番データに混ぜない。
- 元ソース内の固定学校成績・実資格・個別プレゼント・リセットを確認版のビルドから取り除く。9月の実答案・成績APIは確認版では使わない。
- 通常版から確認版へ入る入口は、現在公開中の本体に対する入口だけの変更として別途公開する。作業中の大型更新を同時に出さない。
- 大型更新の正式公開はユーザーから「公開していいよ」と指定された後。本番のなお・りらんのアカウントを維持し、確認版の試験用記録で上書きしない。

## 検証

全体検証に、専用認証、Cookie、オリジン検査、回数制限、保存/再読み込み、本人以外への書き込み拒否、ログアウト、ビルド時の分離を追加している。Cloudflare接続失敗・検証失敗のまま公開しない。

### ログインフォームのブラウザ検証

`node .claude/verify/verify-preview-browser.mjs` は、localhost限定の合成サーバーと新しいブラウザで旧不具合を再現し、スマホ/PC幅のフォーム送信・Cookie・リダイレクトを確認する追加検証。実アカウントと外部サーバーには接続しない。ログイン画面のReferrer-Policyをno-referrerにするとフォームのOriginがnullになるため、same-originを維持する。null/外部Originを受け入れる対処はしない。

2026年9月30日の再指示：今後の変更は必ず確認版アカウントで確認できるよう先に配信し、ユーザーの確認・公開指示を経て本編へ反映する。確認版のログインができないまま本編へ進めない。

### パスワードでプランを自動選択（2026-10-10）
- 最新の指定は、入力したパスワードに対応する Free／Mini／Standard／Pro／UNLIMIT の確認版を開く方式。4桁の設定とプラン選択は不要。
- Free は従来の確認版 u1 の記録と権限を維持し、表示名だけ Free 確認版へ変更する。有料4プランは既存の p_* を維持し、管理者権限は付けない。Standard の入力はユーザー指定の対応を使用する。
- 配信時、専用 Worker Secret `PREVIEW_ACCESS_CODES` に新規pepperと5アカウントのHMAC検証値のJSONを登録する。原文・検証値・pepperはソース・台帳・ログへ書かない。HMAC入力の形式は `access:v1:<UID>:<password>`。既存の秘密値を読み戻さない。
- このSecretがある環境では旧パスワードにフォールバックしない。4桁設定画面の保存も無効にする。専用確認版にだけ適用し、本番認証を変更しない。
- 統合入口の一回限りの引継ぎ券にも確認版UIDを保持し、別プランや管理者へ変わらないことを隔離検証する。
